# 數之背包

「數之背包」是一款以手機直式畫面為主的輕量數學／組合思考小遊戲。專案只使用 HTML、CSS 與 Vanilla JavaScript，不需要安裝套件或執行建置流程，直接開啟 `index.html` 即可遊玩。

## 遊戲玩法

每關會顯示一批商品，以及兩個目標：必須挑選的商品件數 `n`，和背包的目標總重量 `A`。玩家要恰好選出 `n` 件商品，且這些商品在本關的重量總和必須等於 `A`。

- 點選商品卡可放入或移出背包。
- 選滿 `n` 件後仍可取消已選商品，但不能再加入第 `n + 1` 件。
- 如果總重量超過目標，畫面只會即時顯示「超重！」，不會判定失敗。
- 件數與重量同時符合目標時會自動過關。
- 每種難度共有 8 關，必須通過目前關卡才能解鎖下一關。

`assets/products/` 與 `assets/ui/` 目前保留給未來正式素材使用，第一版以 CSS placeholder 顯示。

## JavaScript 檔案責任

- `products.js`：保存商品的固定資料，例如 id、名稱、圖片路徑與官網連結。
- `difficulty.js`：保存三種模式的商品數、每關指定件數、目標重量範圍與干擾距離。
- `generator.js`：一次產生某個模式的完整 8 關，包括目標重量、保證解、干擾項、商品抽樣、配對與洗牌。
- `game.js`：管理目前模式、解鎖進度、各關選取狀態、過關判定與彈窗動作。
- `ui.js`：取得畫面元素、綁定操作事件，以及渲染關卡、背包、商品與彈窗。
- `main.js`：在頁面就緒後啟動遊戲。

這些檔案使用一般 `<script>` 依序載入，不使用 ES module，確保由檔案系統直接開啟 `index.html` 也能執行。

## 三種難度參數

| 模式 | 商品數 m | 八關指定件數 n | A 範圍 | 干擾距離 d |
|---|---:|---|---|---:|
| 簡單 | 6 | 2, 2, 3, 3, 3, 4, 4, 4 | 10–30 | 4 |
| 中等 | 8 | 3, 3, 4, 4, 4, 5, 5, 5 | 20–50 | 3 |
| 困難 | 10 | 4, 4, 5, 5, 5, 6, 6, 6 | 40–100 | 2 |

`d` 是第一版測試參數，之後可依實際遊玩感受調整。

## 關卡生成原理

### A 如何生成

玩家每次開始一個模式時，`generator.js` 會先建立該模式允許範圍內的所有整數，隨機洗牌後抽出 8 個不重複數字，再由小到大排序。因此每次產生的 `A1` 到 `A8` 都在範圍內、嚴格遞增，且不是固定數列。如果 8 個數字剛好形成完整等差數列，生成器會在有限次數內重抽。

### seed solution 如何保證至少一解

每關會先在 `1` 到 `A - 1` 之間抽出 `n - 1` 個不同切點。排序切點後，把 `A` 分割成 `n` 個正整數；這 `n` 個重量的總和必然等於 `A`，而且每個重量都大於 0 且小於 `A`。這組重量就是 seed solution，因此每題至少存在一組合法答案。

### distractor 的 d 如何作用

其餘 `m - n` 個重量是干擾項。產生每個干擾項時，生成器會先隨機挑一個 seed solution 重量 `wi`，再於 `-d` 到 `+d` 之間取偏移量，且只接受 `0 < v < A` 的結果。因此每個干擾項都至少接近一個正解重量，符合 `|v - wi| <= d`。所有嘗試都有固定上限，沒有無限迴圈。

生成完整重量後，系統會隨機抽出 `m` 個不重複商品，將商品與重量隨機配對，最後再洗牌商品卡。干擾項可能讓題目出現其他合法解；這是允許的。

## 為什麼商品重量不放在 products.js

商品重量是每一關的遊戲數值，不是商品的固定屬性。同一個商品在不同關卡可以有不同重量。把重量留在 `generator.js` 動態產生，可避免玩家從商品本身推測答案，也能維持關卡變化。

## Session 行為

進入一個模式時會一次建立完整 8 關，並保存在目前頁面的記憶體中。回到舊關卡、前往已解鎖關卡，或選擇「再玩一次」目前關卡時，題目不會重新生成。只有選擇「再玩一次某模式」或從首頁重新進入模式時，才會建立一套新的 8 關。重新整理頁面後狀態會重置；第一版不使用 `localStorage`。

## 替換正式圖片

### 商品圖片

建議將 128 × 128、透明背景的 PNG 放進 `assets/products/`，再到 `products.js` 把對應商品的 `image` 改成相對路徑，例如 `assets/products/product-a.png`。目前 `ui.js` 使用 `.product-image-placeholder`；加入正式素材時，可在這個容器內以 `<img>` 顯示 `card.image`，並保留既有尺寸比例。

### 背包圖片

建議將 256 × 256、透明背景的 PNG 放進 `assets/ui/`。可在 `.home-backpack` 與 `.game-backpack` 加入背景圖片，或在相同容器中加入 `<img>`。背包格子是獨立的 `.backpack-slots`，替換背景時不需要修改選取邏輯。

### UI 圖示

32 × 32 或 48 × 48 的 PNG 可放進 `assets/ui/`，再替換目前的文字符號。按鈕仍應保留 `aria-label`，避免只靠圖片傳達功能。

## 調整難度參數

所有主要難度值都集中在 `js/difficulty.js`：

- `itemCount`：每關顯示的商品數 `m`。
- `targetCounts`：8 關各自要求的選取件數 `n`。
- `targetRange`：目標重量 `A` 的最小值與最大值。
- `distractorDistance`：干擾項與 seed solution 重量的最大距離 `d`。

調整時請確保商品總數不超過 `products.js` 的可用商品數，而且 `A` 的範圍至少能提供 8 個不重複整數。
